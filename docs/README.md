# Crossmith Docs

- [**DECISIONS.md**](DECISIONS.md) — Phase 0 strategy: name, positioning, tech
  stack with rationale, architecture, MVP scope, risks, rejected alternatives.
  Start here to understand *why* things are built the way they are.
- **architecture/** — deeper dives per layer (detection engine, build engine,
  adapter interface, AI integration) as they're built out.
- **guides/** — task-oriented docs:
  - `getting-started.md` — install and run your first build *(Phase 2/3)*
  - `adapter-development.md` — build a new language/platform adapter *(Phase 3)*
  - `troubleshooting.md` — common problems, especially AV false positives *(Phase 3/5)*

Guides are added as the features they document land — see the
[roadmap](../README.md#roadmap) for what's next.
